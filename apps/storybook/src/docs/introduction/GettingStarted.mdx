## 컴포넌트 가져오기

Vue와 React 구현은 컴포넌트별 서브패스 export를 제공합니다. Nuxt는 Vue 패키지를, Next.js는 React 패키지를 같은 방식으로 가져오며 프레임워크 전용 컴포넌트만 해당 앱 내부에서 사용합니다.

```vue
<script setup>
import Button from '@uxkm/vue/button';
import { Card, CardBody } from '@uxkm/vue/card';
</script>

<template>
  <Card>
    <CardBody>
      <Button variant="filled" color="primary" label="저장" />
    </CardBody>
  </Card>
</template>
```

```jsx
import Button from '@uxkm/react/button';
import { Card, CardBody } from '@uxkm/react/card';

export function SaveCard() {
  return (
    <Card>
      <CardBody>
        <Button variant="filled" color="primary" label="저장" />
      </CardBody>
    </Card>
  );
}
```

현재 패키지는 이 모노레포 안에서 사용하는 private workspace 패키지입니다. 외부 프로젝트에서 패키지 이름으로 설치하는 공개 배포 방식은 별도 패키징 이후에 적용합니다.

## HTML 마크업으로 사용

공통 CSS를 연결하면 Vue나 React 없이도 같은 클래스와 시맨틱 마크업을 사용할 수 있습니다. 각 컴포넌트 문서의 HTML 탭을 기준으로 구조, 상태 클래스와 `aria-*` 속성을 함께 적용합니다.

```html
<link rel="stylesheet" href="/styles/uxkm.css" />

<button type="button" class="btn btn_filled color_primary">
  <span class="btn_label">저장</span>
</button>

<div class="alert color_info" role="alert">
  <div class="alert_body">
    <p class="alert_desc">변경 사항이 저장되었습니다.</p>
  </div>
</div>
```

Button처럼 네이티브 동작만 필요한 요소는 CSS와 마크업만으로 사용할 수 있습니다. Modal, Drawer, Accordion처럼 열림 상태·포커스 이동·키보드 조작이 필요한 컴포넌트는 해당 HTML/Gulp 스크립트 또는 Vue/React 구현도 함께 적용해야 합니다.

## WebSquare 화면 XML에서 사용

각 컴포넌트 문서의 WebSquare 탭에서 XML 호환 마크업을 복사할 수 있습니다. 예제는 공통 CSS 클래스와 접근성 속성을 유지한 fragment이며, WebSquare 화면 XML 루트 안에 배치하는 것을 전제로 합니다.

`xmlns` 선언은 컴포넌트 속성이 아니라 XML 문서 범위의 선언입니다. 화면 루트에서 한 번 선언하고 내부 컴포넌트는 이를 상속합니다. 여러 컴포넌트를 같은 화면에 배치해도 선언을 반복하지 않습니다. 별도 화면 XML이나 WFrame의 `src`로 불러오는 파일처럼 독립적으로 파싱되는 문서는 각 파일의 루트에서 다시 선언하며, `ev`와 `xf`는 해당 접두사를 사용하는 화면에서 추가합니다.

1. WebSquare 화면이 로드하는 스타일에 `uxkm.css`를 연결합니다.
2. Storybook의 WebSquare 탭에서 XML 조각을 복사해 화면에 배치합니다.
3. 정적 HTML 이벤트에 의존하는 컴포넌트는 `ev:onclick`, `scwin` 함수와 프로젝트 데이터 객체에 맞게 연결합니다.
4. 실제 WebSquare 엔진에서 레이아웃, 포커스, 키보드와 데이터 바인딩을 검증합니다.

컴포넌트 탭의 fragment를 기존 화면에 추가할 때는 아래의 `screenRoot`나 네임스페이스 선언을 함께 복사하지 않습니다. 화면 파일을 새로 만드는 경우에만 프로젝트의 기본 화면 템플릿에서 루트 선언을 한 번 작성합니다.

화면 XML 루트에서 네임스페이스를 공통 선언하고, 정적 마크업을 WebSquare 컴포넌트와 이벤트로 연결할 때는 다음과 같이 적용할 수 있습니다.

```xml
<w2:group
  xmlns="http://www.w3.org/1999/xhtml"
  xmlns:ev="http://www.w3.org/2001/xml-events"
  xmlns:w2="http://www.inswave.com/websquare"
  xmlns:xf="http://www.w3.org/2002/xforms"
  id="screenRoot">
  <w2:group id="saveActions" class="form_actions">
    <xf:trigger
      id="btnSave"
      type="button"
      class="btn btn_filled color_primary"
      ev:onclick="scwin.btnSave_onclick">
      <xf:label><![CDATA[저장]]></xf:label>
    </xf:trigger>
  </w2:group>
</w2:group>
```

```javascript
scwin.btnSave_onclick = function () {
  // 프로젝트의 submission 또는 저장 로직을 호출합니다.
};
```

Storybook의 자동 예제는 CSS와 접근성 구조를 우선 보존합니다. `w2:trigger`, `xf:input`, DataList 바인딩처럼 WebSquare 전용 컴포넌트가 필요한 화면은 이 마크업을 기준으로 프로젝트 표준에 맞게 치환합니다.

Container, Grid, Flex처럼 호출 위치의 자식 콘텐츠를 감싸는 구조 컴포넌트는 별도 XML 파일을 WFrame으로 호출하지 않고 현재 화면의 `w2:group`에 공통 클래스를 직접 적용합니다. WFrame은 공통 메뉴처럼 완성된 별도 화면 XML을 `src`로 포함해야 할 때 사용합니다.

WebSquare 탭은 화면 XML 작성 기준을 제공하며 WebSquare 런타임, 라이선스 또는 별도 `apps/websquare` 실행 프로젝트를 포함하지 않습니다.

페이지는 공통 레이아웃을 상속하고 `content` block 안에서 partial이나 컴포넌트를 포함합니다.

```nunjucks
{% extends "layouts/default.njk" %}

{% block content %}
  <main>
    <h1>{{ pageTitle }}</h1>
    {% include "components/basic/Button/button.njk" %}
  </main>
```

반복되는 목록이나 상태는 Nunjucks 데이터와 제어문으로 생성할 수 있습니다. 템플릿 문법은 빌드 시 사라지고 최종 결과에는 일반 HTML만 남습니다.

```nunjucks
{% set actions = [
  { label: '저장', color: 'primary' },
  { label: '삭제', color: 'danger' }
] %}

{% for action in actions %}
  <button type="button" class="btn btn_filled color_{{ action.color }}">
    <span class="btn_label">{{ action.label }}</span>
  </button>
{% endfor %}
```

```html
<!-- 위 템플릿의 빌드 결과 예시 -->
<button type="button" class="btn btn_filled color_primary">
  <span class="btn_label">저장</span>
</button>
<button type="button" class="btn btn_filled color_danger">
  <span class="btn_label">삭제</span>
</button>
```

현재 `apps/gulp`에는 52개 컴포넌트의 `.njk` 소스와 레이아웃 구조가 준비되어 있지만, `gulpfile.js`, 페이지 템플릿, 패키지 실행 스크립트는 아직 스캐폴드 상태입니다. 따라서 현재는 `pnpm dev`가 Gulp 변환을 실행하지 않으며, 실제 `.njk → .html` 빌드 명령은 Gulp 태스크가 연결된 뒤 이 문서의 주요 명령 표에 추가합니다.

복합어 prop은 템플릿에서 kebab-case로 작성하고 이벤트는 `@이벤트명`으로 받습니다. 기본 콘텐츠는 default slot, 아이콘처럼 위치가 정해진 콘텐츠는 named slot을 사용합니다.

```vue
<script setup>
import { ref } from 'vue';
import Button from '@uxkm/vue/button';

const saving = ref(false);

function save() {
  saving.value = true;
}
</script>

<template>
  <Button
    variant="filled"
    color="primary"
    :loading="saving"
    aria-label="변경 사항 저장"
    @click="save"
  >
    저장
  </Button>
</template>
```

named slot은 `#이름`으로 전달합니다. 예를 들어 Button의 `icon-before` slot은 다음과 같이 사용합니다.

```vue
<Button label="추가">
  <template #icon-before>
    <span aria-hidden="true">+</span>
  </template>
</Button>
```

Nuxt에서도 UI 컴포넌트의 prop·이벤트·slot 사용법은 같습니다. 페이지 라우팅이나 `NuxtLink`, `NuxtImg`가 필요한 부분만 Nuxt 전용 구현을 선택합니다.

JSX에서는 `ariaLabel`, `iconBefore`, `onClick`처럼 camelCase prop을 사용합니다. 본문 콘텐츠는 `children`으로 전달하며, 아이콘이나 추가 액션처럼 위치가 정해진 콘텐츠는 해당 React node prop을 사용합니다.

```jsx
import { useState } from 'react';
import Button from '@uxkm/react/button';

export function SaveButton() {
  const [saving, setSaving] = useState(false);

  return (
    <Button
      variant="filled"
      color="primary"
      loading={saving}
      ariaLabel="변경 사항 저장"
      iconBefore={<span aria-hidden="true">✓</span>}
      onClick={() => setSaving(true)}
    >
      저장
    </Button>
  );
}
```

Next.js에서도 공통 UI의 prop·이벤트·children 사용법은 같습니다. App Router의 서버 컴포넌트에서 상태나 이벤트를 사용하는 컴포넌트는 `'use client'` 경계 안에 두고, 경로 이동이나 이미지 최적화가 필요한 부분만 Next.js 전용 구현을 사용합니다.

## 테마

라이트/다크 테마는 루트 요소의 `data-theme`으로 전환합니다. 속성을 지정하지 않으면 시스템의 `prefers-color-scheme`을 따르고, Storybook에서는 상단 툴바의 테마 항목이 같은 속성을 설정합니다.

```html
<html lang="ko" data-theme="light">
<html lang="ko" data-theme="dark">
```

```js
document.documentElement.dataset.theme = 'dark';
```

사용자의 선택을 유지하려면 `localStorage` 등에 값을 저장하고, 첫 화면이 그려지기 전에 `data-theme`을 설정해 테마가 순간적으로 바뀌는 현상을 방지합니다. 저장 값이 없을 때는 속성을 제거하면 시스템 설정으로 돌아갑니다.

```js
const savedTheme = localStorage.getItem('theme');

if (savedTheme === 'light' || savedTheme === 'dark') {
  document.documentElement.dataset.theme = savedTheme;
} else {
  document.documentElement.removeAttribute('data-theme');
}
```
