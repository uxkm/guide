# 디자인 토큰

색상, 간격, 모서리, 타이포그래피, 모션과 레이아웃 값을 의미 있는 CSS 변수로 관리합니다. 프레임워크가 달라도 같은 토큰을 참조하므로 디자인 변경과 테마 전환이 모든 앱에 일관되게 반영됩니다. 앱별 CSS 연결은 **설치 및 사용 › 프레임워크별 스타일 적용**, 간격·타이포 적용 원칙은 **가이드라인 › 파운데이션**을 참고합니다.

## 원본과 배포

```text
packages/styles/
├── foundations/       # 토큰·테마·폰트·reset
├── layouts/           # 앱 셸·사이드바·콘텐츠
├── components/        # 컴포넌트 범위 토큰과 스타일
├── behaviors/         # 공통 동작의 시각 효과
├── shared/            # SCSS 변수와 mixin 진입점
└── index.scss         # 모든 프레임워크가 공유하는 빌드 진입점
        │
        └─ pnpm build:styles
             └─ apps/{html,gulp,vue,react,nuxt,next,storybook}/public/styles/uxkm.css
```

생성된 CSS는 편집하지 않습니다. 토큰 또는 컴포넌트 SCSS를 수정한 뒤 `pnpm build:styles`로 다시 생성합니다.

## 전역 토큰

런타임에 테마나 특정 영역에서 바꿀 값은 CSS 변수로, 브레이크포인트·폰트 스택처럼 컴파일할 때만 필요한 값은 SCSS 변수로 관리합니다. 컴포넌트 스타일은 실제 수치를 반복하지 않고 이 토큰을 조합합니다.

## 의미 색상과 테마

색상은 실제 hex 대신 역할로 이름을 정합니다. `data-theme`이 바뀌면 동일한 컴포넌트가 다른 값을 사용합니다.

## SCSS와 CSS에서 사용

SCSS는 스타일 구조와 컴파일 타임 헬퍼를 제공하고, 실제 컴포넌트 값은 가능한 한 `var()`로 CSS 토큰을 참조합니다. 이 방식은 빌드 후에도 테마 전환과 범위별 재정의를 가능하게 합니다.

```scss
.card {
  padding: var(--space-lg);
  border: 1px solid var(--color-border-subtle);
  border-radius: var(--radius-lg);
  color: var(--color-text);
  background: var(--color-surface);
  font-size: var(--text-size-sm);
  transition: box-shadow var(--transition-fast);
}
```

토큰은 상속되므로 컨테이너에 재정의하면 그 안의 컴포넌트에만 적용됩니다. 전역 값을 바꾸지 않고 밀도나 크기가 다른 영역을 만들 때 사용합니다.

```css
.compact-panel {
  --space-md: 0.75rem;
  --btn-padding-y: var(--space-xs);
  --icon-size: 1rem;
}
```

## 테마 동작

`:root`와 `[data-theme="light"]`에는 라이트 테마가, `[data-theme="dark"]`에는 다크 테마가 적용됩니다. 명시적인 속성이 없으면 `prefers-color-scheme` 미디어 쿼리가 시스템 설정을 선택합니다. 테마별로는 의미 색상의 값만 달라지고 컴포넌트 선택자와 마크업은 바뀌지 않습니다. 앱에서 `data-theme`을 설정하는 위치는 **설치 및 사용 › 프레임워크별 스타일 적용**을 참고합니다.

```css
[data-theme='light'] {
  --color-accent: #3d66c4;
  --color-on-accent: #ffffff;
}

[data-theme='dark'] {
  --color-accent: #386bc0;
  --color-on-accent: #ffffff;
}
```

사용자의 선택을 유지하려면 `localStorage` 등에 값을 저장하고, 첫 화면이 그려지기 전에 `data-theme`을 설정해 테마가 순간적으로 바뀌는 현상을 방지합니다. 저장 값이 없을 때는 속성을 제거하면 시스템 설정으로 돌아갑니다.

```js
const savedTheme = localStorage.getItem('theme');

if (savedTheme === 'light' || savedTheme === 'dark') {
  document.documentElement.dataset.theme = savedTheme;
} else {
  document.documentElement.removeAttribute('data-theme');
}
```

## 컴포넌트 토큰

전역 토큰만으로 설명하기 어려운 값은 컴포넌트 범위 변수로 제공합니다. 예를 들어 `--icon-size`, `--btn-padding-y`, `--input-max-width`처럼 컴포넌트 이름을 접두어로 사용합니다. 각 변수의 실제 기본값은 해당 컴포넌트 SCSS와 Storybook 문서의 디자인 토큰 섹션에서 확인합니다. 페이지나 컨테이너에서 이 변수를 재정의하면 해당 범위만 조정할 수 있습니다.

```css
.compact-actions {
  --btn-padding-y: var(--space-xs);
  --icon-size: 1rem;
}
```

## 변경 원칙

- 같은 의미의 새 값을 프레임워크 앱 안에 하드코딩하지 않습니다.
- 색상은 시각적 이름보다 역할을 나타내는 semantic token을 우선합니다.
- 전역 토큰 추가 전 컴포넌트 범위 값인지 확인합니다.
- 라이트와 다크 테마, 비활성 상태, 포커스 대비를 함께 검증합니다.
- 수정 후 공통 CSS를 다시 빌드하고 Storybook의 양쪽 테마에서 확인합니다.
